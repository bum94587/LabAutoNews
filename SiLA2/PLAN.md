# SiLA 2 digital-twin POC: plan and interface contract

Goal: show a basic scheduler running a workflow through **SiLA 2 virtual drivers** against a
**Hamilton STAR digital twin**, all on Linux with open-source tools, and document it.

## Architecture

```
scheduler/scheduler.py  ──SiLA 2 (gRPC, insecure, localhost)──►  servers/lh_twin   (port 50052)
   runs scheduler/workflow.yaml                                   LiquidHandlerService
   (two device lanes, dependencies,                                 └─ PyLabRobot v1 STAR(simulation=True)
    timed steps)                                                       firmware-level simulator + resource/volume model
                         ──SiLA 2────────────────────────────►  servers/hhs_twin  (port 50053)
                                                                  HeaterShakerService
                                                                    └─ first-order thermal model, accelerated time
run_demo.py: starts both servers as subprocesses, waits for them, runs the scheduler, writes results/.
```

- Python 3.12, uv project at `SiLA2/` (`uv sync`; run everything with `uv run ...` from `SiLA2/`).
- Pinned deps: `sila2[codegen]==0.14.0`, `pylabrobot @ git+https://github.com/PyLabRobot/pylabrobot@7779f506d12755f5f274b4c5cab4d095f4fccb62`, matplotlib, pyyaml.
- Feature definitions: `features/LiquidHandlerService-v1_0.sila.xml`, `features/HeaterShakerService-v1_0.sila.xml`,
  generated by `features/make_fdl.py`. **Do not change the FDL without telling the lead**: the scheduler depends on it.
- Server packages generated with `sila2-codegen new-package` into `servers/lh_twin` and `servers/hhs_twin`
  (installed editable). Implement only `*/feature_implementations/*_impl.py` (+ helper modules beside them,
  + `server.py` name/description). Leave `generated/` alone.
- Start a server: `uv run python -m lh_twin --port 50052 --insecure --disable-discovery` (hhs_twin: 50053).
- Client (scheduler) uses the dynamic client: `from sila2.client import SilaClient;
  c = SilaClient("127.0.0.1", 50052, insecure=True); c.LiquidHandlerService.Aspirate(Plate="src", Column=1, VolumeUl=50.0)`.
  Observable commands: `inst = c.LiquidHandlerService.Transfer(...)`; iterate intermediate responses
  via `inst.subscribe_to_intermediate_responses()`, final via `inst.get_responses()` (check exact API in sila2 0.14).

## LH twin (servers/lh_twin) contract

- Twin core: PyLabRobot v1 `pylabrobot.hamilton.star.STAR(simulation=True)` (firmware-level simulator built from a
  recorded real STAR configuration). Verified to work in this env:
  `TIP_CAR_480_A00` + `hamilton_96_tiprack_300uL_filter`, `PLT_CAR_L5AC_A00` + `cor_96_wellplate_360uL_Fb`
  (any working carrier/labware is fine, this is a POC), `deck.assign_child_resource(carrier, track=N)`,
  `star.pipettes.pick_up_tips(tips["A1:H1"])`, `.aspirate(plate["A1:H1"], volumes=[...])`, `.dispense(...)`,
  `.drop_tips(tips["A1:H1"])`, volume tracking via `set_volume_tracking(True)` and `well.tracker.set_volume(v)`,
  `well.tracker.get_used_volume()`.
- PyLabRobot is async; the sila2 server is threaded/sync: run one asyncio event loop in a background thread and call
  coroutines with `asyncio.run_coroutine_threadsafe(...).result()`. Serialise LH operations with a lock.
- **POC deck layout** (resource names are part of the contract):
  - tip carrier `tip_car` (track 1): `tips` (300 uL filter tips, 96)
  - plate carrier `plate_car` (track 7): site 0 `compounds` (200 uL/well), site 1 `nadph` (200 uL/well),
    site 2 `reaction` (300 uL/well, "microsomes in buffer"; conceptually sits on the heater-shaker),
    site 3 `quench` (150 uL/well, "cold acetonitrile")
  - Use plates big enough for these volumes (e.g. a 2 mL deep-well plate if a carrier accepts it; otherwise scale
    volumes down and record it in INSTRUMENT notes).
- Firmware trace: capture every firmware command string the STAR driver sends to the simulator and its reply (find the
  hook in `pylabrobot/hamilton/star/driver/{master,simulator}.py`, e.g. wrap `send_command`/`_send` or a logger), keep
  an in-memory list of `{index, time, command, reply}`; `GetFirmwareTrace(SinceIndex)` returns it as JSON.
- `Status` observable property: "idle" / "busy: <operation>" / "error: <msg>". `InstrumentInfo`: model, PLR commit, simulator.
- Errors: raise the generated `NotInitialized` / `LiquidHandlingError` defined-execution errors.
- `Transfer` observable: intermediate `Step` strings for pick up / aspirate / dispense / drop, final `Message`.
  Each transfer uses the next unused tip column (track this in the twin); fail with LiquidHandlingError when out of tips.

## HHS twin (servers/hhs_twin) contract

- First-order thermal model: dT/dt = (T_target - T) / tau, tau = 30 s **simulated**; time acceleration factor 10 (so a
  25->37 C ramp takes a few real seconds). Start at 22.0 C. Reached when |T - target| <= 0.5 C.
- `SetTemperature` observable with intermediate `CurrentTemperature`; final `ReachedTemperature`.
  `TemperatureOutOfRange` outside 4-70 C. `StartShaking(Speed)` 200-3000 rpm else `SpeedOutOfRange`; `StopShaking`.
- `CurrentTemperature` observable property; `ShakingSpeed` property.
- Keep a log of state changes for the results (expose nothing extra over SiLA; write to stdout/log is fine).

## Scheduler (scheduler/) contract

- `scheduler/workflow.yaml`: a mini **microsomal-stability** run, time-compressed (1 "minute" = 2 s):
  1. lane hhs: SetTemperature 37 (observable)       | lane lh: Initialize
  2. lh: Transfer compounds col1 -> reaction col1, 50 uL
  3. wait for hhs at temperature (dependency)
  4. lh: Transfer nadph col1 -> reaction col1, 50 uL  -> marks t0
  5. hhs: StartShaking 600
  6. for t in [0, 1, 2, 3, 5] min: hhs StopShaking; lh Transfer reaction col1 -> quench col(k), 50 uL; hhs StartShaking
     (timed: start at t0 + t)
  7. hhs StopShaking; hhs SetTemperature 22
  8. lh GetWellVolumes for each plate; lh GetFirmwareTrace(0)
- `scheduler/scheduler.py`: loads the YAML, builds a small DAG (step ids, device, command, params, depends_on,
  start_after_t0_s), runs device lanes concurrently (threads), each device executes one step at a time, observable
  commands stream intermediate responses into the log. Writes `results/timeline.json` (step, device, start, end,
  status, responses) and prints a live log.
- `run_demo.py` (in SiLA2/): start both servers as subprocesses (ports above, --insecure --disable-discovery), wait until
  they accept connections, run the scheduler, then write to `results/`: `timeline.json`, `firmware_trace.json`,
  `well_volumes.json`, `gantt.svg` (matplotlib), `plate_volumes.svg` (heat maps of the 4 plates), `run_summary.md`
  (what ran, timings, key numbers). Stop servers cleanly. Exit non-zero on any failed step.
- `tests/test_smoke.py`: quick end-to-end test (can be run with `uv run python -m pytest -q tests` if pytest added,
  or plain `uv run python tests/test_smoke.py`).
